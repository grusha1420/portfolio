## Дизайн и брендинг

| Вопрос | Решение |
|--------|---------|
| Цвета сегментов | На первой версии — любые placeholder-цвета; должны легко меняться позже (CSS-переменные / конфиг темы) |
| Тёмная / светлая тема | Обе нужны; по умолчанию — **системная тема устройства** (`prefers-color-scheme`) |
| Брендбук | Нет — шрифты и палитра выбираются при вёрстке |
| Язык интерфейса | **Только английский** |
| Референсы | Скриншоты лежат в этой же папке: `Fullpage Kenney.png`, `Fullpage YNG.png`, `polygoniq.png`, `work.png`, `about.png`, `contact.png` |
| Волновая анимация | Как у [kenney.nl](https://kenney.nl/) — **без упрощений** |

### Выводы для реализации

- Использовать CSS-переменные для цветов сегментов и темы, чтобы потом менять без правок компонентов.
- Подключить переключение темы (например, `next-themes`) с дефолтом `system`.
- Волны — отдельный UI-компонент, реализованный по референсу Kenney (SVG/CSS-анимация).

## Hero-сегмент

| Вопрос | Решение |
|--------|---------|
| Фон | Полноэкранная анимированная GIF; на старте — **placeholder**, заменяется позже |
| Wireframe-иллюстрация | **Два слоя** одного изображения: ч/б wireframe снизу, цветной сверху с управляемой прозрачностью |
| Эффект «раскрашивания» (desktop) | Прозрачность цветного слоя зависит от **вертикальной позиции курсора** относительно Hero-сегмента (см. [polygoniq.com](https://polygoniq.com/)) |
| Эффект (mobile) | Прогресс прозрачности по **скроллу всей страницы** (0% → 100%), не по курсору |
| Cal.com | **Popup-модал** по кнопке — как у [YNG.CGI](https://www.yunusgezginci.com/): затемнённый фон, Cal.com embed в центре, кнопка закрытия (×) |
| WhatsApp / Telegram | Контакты добавляются **через админку** (раздел Contact) |

### Выводы для реализации

- В концепте исправлено: GIF — фон **Hero**, не хэдера.
- Wireframe: два `<img>` или два слоя с `mix-blend-mode` / `opacity`.
  - Desktop: `mousemove` — прозрачность от позиции курсора относительно Hero.
  - Mobile: `scroll` — прогресс от 0 до 1 по scroll position **всей страницы** (`scrollY / (documentHeight - viewportHeight)`).
- Cal.com: модальное окно с `@calcom/embed-react` или iframe; backdrop + `×` для закрытия (референс — скриншот YNG popup).
- Hero-контент (текст, GIF, wireframe-слои) редактируется в админке → раздел **Content**.

## Featured Work и Work Gallery

| Вопрос | Решение |
|--------|---------|
| Критерий попадания в Featured | Все работы с флагом **`featured`** |
| Категории | Создаются **в админке** (не фиксированный список) |
| Layout галереи | **Masonry** |
| Сортировка | Не нужна |
| Поиск (Work Gallery) | Только по **названию** и **категории** |
| Объём на старте | **3 работы**, с ростом до **~30** |
| URL галереи | `/work` — список всех работ |
| URL работы | `/work/[slug]` — slug задаётся в админке |
| Cover vs галерея | **Отдельное cover-изображение** для карточки + отдельная галерея на странице работы |
| Видео | Только **YouTube embed** по ссылке |
| Похожие / prev-next / share | **Не нужны** |

### Выводы для реализации

- Masonry: CSS columns или библиотека (например, `react-masonry-css`); учесть lazy-load изображений при 30 работах.
- Поиск — фильтрация на клиенте достаточна при 30 записях; server-side не обязателен.
- Категории — отдельная сущность в БД или tags с CRUD в админке.
- Поле `featured: boolean` + checkbox в форме редактирования работы.

## About и Blog

| Вопрос | Решение |
|--------|---------|
| Основная статья About | Blog post с флагом **`isMain`** |
| URL статей | `/blog/[slug]` — slug задаётся в админке |
| Формат контента | **MDX** — изображения и ссылки внутри текста |
| SEO | **Нужны** meta title, description, OG-image для работ и статей |
| Rich text editor | **mdxEditor обязателен с первой версии** — WYSIWYG без отдельного preview |

### Выводы для реализации

- Одна статья с `isMain = true` отображается как основная на `/about`; остальные — карточками.
- mdxEditor с загрузкой изображений через Uploadthing.
- SEO-поля в формах Work и Blog; OG-image — отдельное поле или cover.

## Contact

| Вопрос | Решение |
|--------|---------|
| Поля формы | Имя*, компания, email*, телефон, сообщение (* — обязательные) |
| После отправки | Только **запись в БД** → раздел Requests в админке |
| Уведомления (email/TG) | **Не нужны** |
| Защита от спама | **Не нужна** |
| Соцсети и ссылки | Произвольные из админки: текст, URL, иконка (URL или загрузка в Uploadthing) |
| Fallback иконки | Если иконка не задана — **Lucide `Link`** (универсальная иконка ссылки) |
| WhatsApp / Telegram | Тоже через админку |
| Cal.com | **Popup-модал** — тот же паттерн, что в Hero (см. референс YNG.CGI) |
| На доп. страницах | **Тот же компонент Contact**, что на главной (не упрощённый footer) |

## Админка

| Вопрос | Решение |
|--------|---------|
| Авторизация | Один пароль из **env** — достаточно |
| Content (Hero + About) | Редактируются: **текст, картинки, GIF, wireframe-слои** |
| Featured | Checkbox при редактировании работы |
| Видимость работ / статей | По умолчанию **скрыты** (`hidden = true`) — доступны только по прямой ссылке; снятие checkbox делает их видимыми в галереях и списках |
| mdxEditor | Обязателен в v1 |

### Модель публикации

```
hidden = true  (default) → доступно только по /work/slug или /blog/slug
hidden = false           → показывается в галереях, Featured (если featured), списке статей
```
